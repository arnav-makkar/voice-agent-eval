01 · The missing core

What is the failure-derived dataset?

It is a test set created from the exact point where real calls failed. Real traces supply the problem; controlled synthetic variants test whether a repair generalizes beyond the original wording.

Real traceFind the first breaking turn.
Freeze contextKeep only what the agent had seen.
Vary one factorLanguage, objection, interruption or channel.
Define truthExpected next state + forbidden behavior.
Run gatesDevelopment, regression and sealed held-out.
Necessary

Why the 20 calls are not enough

The calls reveal failures, but they are too small for prompt search and generalization claims. Without derived variants, an optimizer can memorize exact transcripts or satisfy static phrases while failing on a slightly different caller.

Important boundary

Synthetic tests are not final voice proof

They cheaply select and reject candidates. The final evidence remains matched V12 versus V13 calls through Sarvam STT, reasoning, TTS and turn-taking.

03 · The complete system

GEPA is one box—not the self-improving system.

The system is the governed loop around the optimizer. The 20 calls are deliberately imperfect baseline samples—the starting point, not a target. Reviewed annotations establish reference truth about what occurred. Gemini supplies scalable text intelligence, Python protects exact facts, humans resolve ambiguity, MLflow preserves lineage, and Indus supplies final voice proof.

Exact truth

Python verifier

Amounts, dates, eligibility, allowed dispositions, forbidden transitions, output consistency and split isolation. Gemini cannot overrule these checks.

Semantic intelligence

Gemini 3.6 Flash

Creates controlled variants, plays hidden-state callers, judges directness and objection handling, identifies evidence spans, and supplies reflection feedback.

Decision authority

Human review

Freezes reference annotations, calibrates the judge, reviews generated regression/held-out rows, approves prompt diffs and owns promotion or rollback.

How we prevent one Gemini model from grading itself blindly
Caller, agent and judge run in separate requests with separate system instructions. Hidden caller state is never included in the agent request. The judge receives a frozen rubric and must return evidence spans in structured JSON. Exact facts are checked independently by Python. Judge outputs are calibrated against reviewed human labels, and final voice calls—not Gemini simulations—decide release.

04 · GEPA truth

Are we using Optimize Anything?

Yes—the local Python API. The implementation imports gepa.optimize_anything and calls oa.optimize_anything(...). It is not calling a separate hosted “Optimize Anything” HTTP service.

import gepa.optimize_anything as oa

result = oa.optimize_anything(
  seed_candidate={"prompt": seed},
  evaluator=evaluate_policy,
  dataset=POLICY_CASES[:6],
  valset=POLICY_CASES[6:],
  config=config,
)
Current run is bounded
  • GEPA version: 0.1.4.
  • 10 static policy contracts: 6 development + 4 validation.
  • reflection_lm=None.
  • Custom deterministic EvidenceProposer.
  • 2 candidates returned by the GEPA engine.
  • 1 aggressive control appended by our release harness.
Proved

Contract coverage

The V13 text explicitly covers ten known prompt rules and beats the V12 seed on that static suite.

Not proved

Conversation improvement

No real caller simulation has yet shown that V13 reaches more valid outcomes than V12.

Not proved

Voice TSR lift

No matched V13 voice round has been recorded or scored. The current 20%→100% number must never be called TSR.

What “proper GEPA” means for the final experiment Rerun Optimize Anything with the 120 failure-derived development tasks, deterministic plus Gemini semantic feedback, real generated next replies/multi-turn rollouts, Gemini-powered reflection, at most three candidates, immutable regression checks, and a sealed held-out set. The current GEPA run is a valid pipeline smoke test and prompt linting experiment—not the final optimization evidence.
