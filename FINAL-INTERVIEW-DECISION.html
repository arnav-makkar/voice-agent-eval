01 · Core separation

Evaluation measures. Improvement changes.

These are independent engines connected by versioned artifacts. The improvement engine cannot rewrite success definitions, judges, thresholds or final tests. This separation is what makes the loop scientifically credible and easy to explain.

Engine A · evaluation

EVA-inspired VoiceEval

  • Runs baseline or candidate against identical scenarios.
  • Validates the simulated caller before scoring.
  • Measures conversation, execution, voice and reliability.
  • Produces evidence—not prompt edits.
→ emits
EvaluationRun

run_id · version · scenario · audio · trace · tool events · state diff · validity · metrics · first break · failures

→ consumes
Engine B · improvement

Our ImprovementLab

  • Clusters failures and assigns component ownership.
  • Creates development tests and repair hypotheses.
  • Runs GEPA, manual and component-specific repair arms.
  • Produces versioned candidates—not release claims.
CandidateVersion returns to the same frozen VoiceEval → exact regression gates → fresh final test → matched Indus voice canary → promote / hold / rollback → new production traces begin the next cycle.
Evaluator invariant

Freeze measurement during a comparison

Scenario definitions, simulator policy, evaluators, thresholds and final-test data stay fixed while candidates compete. Evaluator improvement happens as a separately versioned experiment.

Improver freedom

Use more than GEPA

GEPA is the prompt branch. Other branches can repair extractors, tools, workflows, policies, knowledge, runtime and voice configuration—but only when the failure owner points there.

Release authority

Neither engine deploys alone

A release controller enforces per-case gates and records the human-approved decision. “Self-improving” means a repeatable governed loop, not autonomous production mutation.

07 · Final proof design

Predeclare what counts as improvement

Task success remains primary, but it cannot compensate for a new severe regression. Report Accuracy, Experience and Reliability separately; never compress them into a single opaque “agent score.”

Accuracy

Did the task finish truthfully?

Scenario-specific terminal-state assertions, policy adherence, entity fidelity, tool validity, final state and spoken claim versus executed effect.

Experience

Was the route efficient?

Opening length, progression, redundant turns, dead air, latency, interruption recovery, language adaptation and caller burden.

Reliability

Does it work repeatedly?

pass@1 for average performance, pass@k for capability ceiling and pass^k for consistent success across repeated trials.

A

Business-win route

The candidate produces more exact matched task wins than V12, with zero new P0, no safety/integrity regression, protected terminal states and acceptable experience.

B

Quality route under a ceiling

The candidate preserves the exact task-win count and materially reduces integrity, repetition or experience failures, with zero new P0. Report this as task non-degradation plus quality improvement—not TSR lift.

11 · Definition of done

Interview-ready means evidence, not a positive number

The final result may be promote, hold or rollback. A well-supported hold is a successful framework outcome. These are the completion conditions.

Truth is owned

All critical baseline labels and evidence turns are reviewed, evaluators expose agreement, and each result states its provenance and uncertainty.

Execution is real
