01 · The objective take

One paragraph of truth

CURRENT DEFENSIBLE CLAIM

A governed evaluate → diagnose → improve → gate loop exists around a real deployed Sarvam agent — and it is provably honest about what it has not yet proven.

Loopline separates three powers: an EVA-inspired evaluation engine (deterministic task/state/tool truth first, LLM judges second), an improvement engine (manual, GEPA, extractor and component repair arms), and an independent release controller (per-case hard gates, sealed finals, promote/hold/rollback). The candidate V15 swept the 30-scenario stateful text suite and won the sealed 12-case final 9/12 vs 5/12 with zero task regressions — and is correctly held, because a real tool side effect and a matched live voice comparison have not run yet. The strongest single asset is the rejection of the GEPA finalist at 28/30 for one P0 guardrail regression: proof the gate is independent of the optimizer.

The candidate passed a sealed text final, but remains held until a real tool effect and matched V12/V15 voice suite pass the frozen gate.”

03 · What is genuinely good

Eight things a Lead PM panel will respect

GOVERNANCE

The optimizer lost, and the system proved why

The GEPA finalist scored 28/30 — higher than baseline by 12 repairs — and was rejected for one P1 state regression and one P0 guardrail regression (an unauthorized payment-confirmation pattern at turn 4). An aggregate gate would have shipped it. The per-case gate held it. That is the product.

MEASUREMENT

Deterministic truth outranks LLM opinion

Task success is decided by state, tool and disposition assertions against fresh per-trial SQLite state. Gemini grades only what cannot be executed — progression, concision, faithfulness — and can never override an executable failure. improvement_cannot_mutate_evaluator: true is enforced, not aspirational.

HONESTY

The project demoted its own evidence, twice

The 200-case library lost held-out status when source-trace overlap was found. The 20 calls were downgraded from “gold” to “provisional.” Failed candidates, failed provider attempts and a compromised split all survive in the record. Nothing was quietly repainted.

INTEGRATION

The live path is real, not reconstructed

ElevenLabs realtime caller ↔ project-owned EVA adapter ↔ Samvaad bidirectional WebSocket ↔ the actual deployed Shubh agent. Not a batch STT→LLM→TTS loop. Provider evidence (AGENT_ENDS, 45.5 s, 0.92 s mean response) is preserved and replayable in the UI with audio.

DIAGNOSIS

The one live run already earned its keep

Task passed, experience failed: Shubh asked for confirmation again after an explicit pay-now agreement. EVA-A 1.00 / EVA-X 0.667 with the first defect localized to a turn. One run produced a prompt-owned, testable, fixable finding — the loop demonstrated on real audio.

PORTABILITY

The domain pack is a real boundary

EMI is a config artifact — goals, state, tools, dispositions, languages, assertions — not hardcoded logic. A hospital-appointments pack passes schema smoke tests. The honest wording ships with it: schema portability proven, second-domain performance not.

MULTILINGUAL

Hindi/Hinglish/English/Punjabi today

Scenario coverage, language-switch rules and judging span four language modes now. Upstream EVA lists multilingual as future roadmap. For Sarvam's market this is not a checkbox — it is the product context, and it is already in the fixtures.

COST CONTROL

Session budgets exist because a mistake taught them

An early overnight run burned ~63 Sarvam credits on scripted audio loops that proved little. The response: hard session caps, dry-run-first wrappers, no automatic paid retries, and a stop rule against optimizer runs before live evidence. The scar tissue is now policy.

04 · What is weak, missing, or newly found

The gap list — ranked by what it blocks

Items marked BLOCKING gate the final claim. Items marked CREDIBILITY will be probed in the interview. Two items were found in this session's review and are new information.

BLOCKING
Zero live tool side effects — execution truth unproven in production runtime

The FastAPI/SQLite tool service (auth, idempotency, run isolation, 3 endpoints) is built and tested, but the Indus test runtime dropped the stored credential on the one attempt. Until one record_promise_to_pay flows Indus → HTTPS → state diff, “say/do consistency” is a text-mode claim only. Unblock path in Gate 2 below uses Sarvam's documented api_key auth + workspace Secrets + IP allowlist.

BLOCKING
No matched live voice pair — the headline experiment has not run

The 18-record V10 protocol (12 core + 6 acoustic-risk) is frozen with hashes and dry-runs pass, but 0 of 36 provider sessions have executed. Every voice-lift claim is empty until this runs — and the framework is correctly refusing to make one.

BLOCKING
Owner has not reviewed the 20 labels; exposed API key unconfirmed as rotated

Calibration is against Codex-assisted labels. Twenty calls ≈ 2–3 focused hours of owner review. The key pasted into an earlier chat must be treated as exposed until rotation is confirmed at account level — this is a 5-minute action and it gates any public demo.

CREDIBILITY
Single judge family end-to-end (all Gemini)

Gemini generated scenarios, drove candidate experiments and judges semantics. Upstream EVA splits judges across three families (deterministic + Claude for faithfulness + GPT for experience + Gemini for audio) and names same-family bias as a limitation. Cheap fix that needs no new calls: re-score the 24 frozen fresh-final episodes plus the live transcript with a second judge family and publish the agreement/disagreement table.

CREDIBILITY
n=1 live, trials=1 planned — reliability is unmeasured

EVA's leaderboard shows a median pass@k → pass^k drop of 0.44 on accuracy: single-trial results systematically overstate deployment reliability. The matched suite runs trials=1 for budget reasons. Pre-declare this limitation and, if credits allow, add 3 trials on 3–4 core records to produce the first pass^k slice.

CREDIBILITY
Sealed final is thin: 12 cases, p = 0.125

Correctly reported as diagnostic. Expect the question “would you ship on p = 0.125?” The answer is no — text gates screen candidates; the matched voice suite and per-case severity gates decide. Rehearse that answer; it is the right one and it is already the design.

FOUND TODAY
V15 prompt instructs a tool the live runtime does not expose: record_disposition

In text mode record_disposition is a real environment action (validated against the 12-value enum, with a runner fallback). Live, the tool service has only 3 endpoints — a literal call would 404 — and the Indus adapter synthesizes disposition from output variables after the call. Decision needed at Gate 3: keep disposition as an output variable (recommended; no evaluator change), document the prompt line as a known deviation, and watch for it in the 3-call pilot. If the live agent audibly fumbles trying to “call” it, that is a tool-contract failure → route to repair → V16 with a new hash — never a silent prompt edit.

05 · Self-improvement, validated

GEPA is validated — as one arm of a portfolio, and the evidence agrees

The assignment asks for self-improvement with GEPA as the current method. The correct Lead-PM position, backed by this project's own data: keep GEPA, bound it, and grow a layered portfolio as evidence and volume justify each layer.

VALIDATED

What GEPA did here, for real

A genuine local gepa.optimize_anything search ran with full-episode failure feedback; proposals, reflections, Pareto lineage and scores are preserved in MLflow. Its finalist reached 28/30 — objectively strong prompt search.

BOUNDED

What GEPA cannot do

Define business truth, validate simulators, create tool state, prove side effects, decide failure ownership, repair extractors/workflows, run matched voice evaluation, or approve release. It proposes text. The framework decides. Its finalist introduced a P0 guardrail regression the gate caught.

DISCIPLINED

When to run it again

Only after the frozen live evaluation localizes a prompt-owned failure. Optimizer volume is not evidence; a second seed now would optimize against text-mode noise. This deferral is pre-declared in the audit as not_required_for_current_gate.

HARD QUESTIONS — ANSWERS THAT ALREADY EXIST
Why not just GEPA? Isn't this over-built?

A prompt optimizer cannot define truth, validate a simulator, prove a side effect, or approve a release. Ours produced a 28/30 candidate with a P0 guardrail regression — the gate caught what the score hid. The framework is what made GEPA safe to use.

Your final is 12 cases, p = 0.125. Would you ship on that?

No — and I didn't. The text final screens candidates cheaply; promotion requires the matched live suite plus per-case severity gates where a single P0 vetoes any average. I report exact paired counts instead of dressing 12 cases in significance language.

Gemini generates and Gemini judges. Why should I trust the scores?

Deterministic state/action/tool checks control every gate; Gemini only grades what can't be executed. Outcome-level agreement with labels is 1.00/0.80; I publish the weak diagnostics too (0.25 owner agreement). Mitigations queued: owner-truth calibration and a second judge family on the frozen episodes — upstream EVA does the same for the same reason.

What did the one live call actually prove?

That the full path is real — live duplex audio against the deployed agent, provider-attributed termination, scoring on preserved artifacts — and that the evaluator finds product truth: the task succeeded while the experience failed on a redundant confirmation. It proves integration and diagnosis, not reliability or lift; n=1 is why the matched suite exists.

Why ElevenLabs as the caller when you're testing Sarvam?

The caller must be independent of the system under test, and EVA officially supports ElevenLabs as the realtime simulator. Samvaad stays the complete black-box agent under test; a Samvaad-vs-Samvaad setup would double session cost and couple simulator to subject.

Your baseline already commits 9/10. Where's the headroom?

That ceiling is a finding, not a flaw — I pre-declared two promotion routes: more matched task wins, or same wins with materially fewer integrity/repetition defects. Route B is quality improvement under a ceiling and is never reported as TSR lift. The live run's redundant-confirmation defect is exactly Route-B surface.

Would this survive a million SBI/LIC calls?

The control loop transfers; the substrate must be built: ingestion, redaction, outcome joins, stratified human review, distributed scoring, drift and canary infrastructure. My first deliverable on that corpus is a calibrated baseline and a ranked failure taxonomy — anyone who promises an immediate prompt fix on a million calls is describing an experiment without a control.

What would you do with model weights access?

Nothing until the evaluator is owner-calibrated. Then the ladder is SFT on verified traces → KTO, because the release gate already emits the binary outcome signal KTO consumes → RLVR-style methods where verifiable rewards exist. Weight updates inherit every measurement flaw, so measurement matures first.

What broke along the way? What would you do differently?

I burned ~63 credits on an overnight run that produced scripted audio loops, not adaptive evaluation — that mistake became the session-budget and dry-run-first policy. I'd stand up the tool-auth path on day one (it is now the binding gate), and I'd bring a second judge family in earlier. I also spent the first week optimizing before measurement was trustworthy — the audit that killed that version of the project was its most valuable day.

What's the product here, if the candidate might lose?

The release decision system. A correct hold on a bad candidate saves a compliance incident; a correct promote compounds weekly. Evaluation-as-infrastructure also unlocks outcome-based pricing — you can only bill per successful call if success is measured in a way both sides trust.

10 · How it was done

The story arc is the judgment story — ten beats

If asked “walk me through how you worked,” this is the arc. Each beat raised the evidence bar and demoted the previous stage's proof — which is exactly what a self-improving system's operator has to be willing to do.

1 · The benchmark fantasy (3 Aug)

First plan: a 14-day, three-domain synthetic τ-bench build. Impressive, license-audited — and entirely simulated. Its lasting gifts: pre-registered GEPA skepticism and the rule “if a number can't be re-run on camera, cut the number.”

2 · The reality pivot (17 Aug)

Traded three imagined domains for one real deployed Indus EMI agent. First evidence purge: the early 150-scenario corpus declared inadmissible; only controlled real calls count as seed evidence.

3 · The caller becomes an instrument

Recording protocol with hidden cards, frozen fictional facts, anti-bias rules and deliberate negative controls — “a failed call is valuable evidence.” Twenty V12 calls frozen as the discovery corpus.

4 · The same-day self-audit

Hours later: labels demoted to provisional, the first GEPA run reclassified as a pipeline smoke test, “20%→100% must never be called TSR.” The habit of auditing one's own claims is set.

5 · Framework becomes the product (18 Aug)

Reframed as a domain-neutral governed loop: replaceable contracts, repair registry, GEPA demoted to one entry. Success redefined from “candidate wins” to “every cycle produces an auditable decision.”

6 · The research reset (19 Aug)

EVA, τ-Voice and VAmoS audited and adopted selectively — realtime validated simulation and A×X separation from EVA, perturbations from τ-Voice, execution truth from VAmoS — explicitly rejecting wholesale cloning.

7 · Gates harden

Aggregate scoring replaced by per-case severity gates with preserved-win protection — the exact rule that later rejected the GEPA finalist despite its 28/30.

8 · The text loop completes

V13 and V14 rejected for regressions; V15 selected at 30/30 (governing rescore, lineage disclosed); sealed 12-case final won 9/12 vs 5/12 with exact paired reporting and no significance theater.

9 · The live path becomes real

After a costly false start with scripted audio loops (disclosed, budgeted against), a genuine ElevenLabs↔Samvaad duplex run is captured, scored, and shipped into the product UI with its defect on display.

10 · The deliberate withhold (today)

Everything local verifies; four evidence gates stay open on purpose. The success condition was rewritten: run the frozen fair evaluation, preserve every artifact, and let the independent controller make the correct promote / hold / rollback call.
