The agent under test

A framework proves nothing against a toy. The subject is a real agent deployed on Sarvam Indus, doing a job where almost every outcome is a record it must write.

The premise

A customer bought a Samsung Smart TV on EMI and has fallen behind. The agent phones in Hindi and Hinglish to resolve it: take the payment, agree a date, or find out why not.

Every conversation ends one of a few ways, and each one is a different record: money taken, a promise with a date, a callback booked, a dispute filed, a human brought in. That is what makes this a hard test. The agent can sound perfect and still leave the account untouched.

What it can actually do

Six actions. Everything else the agent produces is speech, which changes nothing.

ActionWhen it must fireWhat it records
check_payment_status The customer questions the amount, or claims they already paid Reads the live account rather than answering from memory
record_promise_to_pay Any commitment to pay, now or later The amount and a resolved calendar date (not "tomorrow")
schedule_callback The customer asks to be called another time The agreed window, so a later campaign honours it
record_dispute The customer disputes the amount or the debt itself The stated reason, which pauses collection
escalate_to_human Distress, alleged fraud, or anything needing a person Queues a human. Without it, nobody is called
record_call_outcome Every call, exactly once, at the end How the call ended, which routes what happens next

The rule that matters. Saying "I have noted your payment date" is not the same as calling record_promise_to_pay. One is audio. The other is the only thing the business can act on.

How it is built

ComponentChoice
PlatformSarvam Indus, deployed and live. Every test in this study ran against the real agent, never a copy
Conversation modelSarvam Pro, handling the dialogue
Tool-calling modelLlama 3.1 70B, a separate and smaller model that decides which of the six actions to take
ChannelsOutbound telephony, and a text channel for scale testing

Worth noting for later. The model that talks and the model that acts are different. Every failure in the next section is a failure of the second one, which is exactly the split the framework is built to expose.
