A framework for self-improving voice agents · validated on a live Sarvam Indus agent

A framework that makes deployed voice agents improve themselves

It used to promise customers things it never actually recorded. An automated loop found that habit, rewrote the agent to remove it, and proved the fix on 200 conversations including 20 real phone calls.

The framework, in one view

Evaluate

Every action an agent takes lands in a permanent log it cannot edit. Grading compares the log against what each situation required. What the agent says never decides a score.

Improve

A label-free monitor finds promises with no matching record. Those failures become replay cases, and an automated search rewrites the agent's instructions against them.

Govern

A rewrite ships only if it wins on held-back cases, regresses no safety case, and clears the measured noise floor. Every version is fingerprinted; rollback is the previous fingerprint.

What is framework and what is adapter. The loop, the log, the grading, the gates and the monitor are agent-agnostic. Onboarding a new agent means writing a thin adapter: its tool list, the end state each situation should produce, and the failure types that matter in its domain. The pilot's adapter was an EMI collections agent in Hindi and Hinglish; the loop never knew that.

The validation study

One live production-grade agent on Sarvam Indus, run through the full loop end to end: baseline measured, failures diagnosed and filed, the rewrite generated and gated, then everything re-measured on three independent channels, including 20 real phone calls.

The validation case

The subject agent calls customers whose loan instalment is overdue, in Hindi and Hinglish, and tries to resolve the situation: take a payment, agree a date, book a callback, log a dispute, or escalate to a human being. A hard test for execution truth, because almost every outcome is a record it must write.

The loan

A Samsung Smart TV bought on EMI. ₹4,416 overdue, instalment 7 of 12, 17 days late.

The tools

Six actions it can take: check the balance, log a promise, file a dispute, book a callback, escalate to a human, record the outcome.

The catch

Saying it did one of those things is not the same as doing it. That gap is the whole story.

Three separate proofs

A result that only shows up in one kind of test is a result you should not trust. This one was measured three independent ways, and all three moved together.

Why three tiers instead of one big test

Each tier answers a question the others cannot.

  • Typed chat is cheap enough to run 180 times, so it is the only tier that can carry statistics.
  • Phone calls put a real person on a real line with real speech recognition, interruptions and background noise. Nothing is retryable.
  • Voice to voice has a synthetic caller speak to the agent over live audio, which makes voice behaviour repeatable in a way a human caller never is.

The statistics live in the first tier. The other two exist to show the gains survive contact with real speech.
