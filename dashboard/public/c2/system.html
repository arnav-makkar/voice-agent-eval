Section 2 · The instrument

Three channels, one journal, and metrics that cannot be talked into

The evaluation system is built like a measuring instrument: a frozen benchmark, a controlled tool backend, deterministic scoring wherever possible, judged scoring where speech quality demands it — and an audit trail for the instrument itself.

Architecture

The benchmark

PropertyDesign
200 scenarios20 hand-authored originals + 180 generated across 15 failure families — payment, promises, callbacks, disputes, escalations, guardrails, privacy, ledger interrogation. Frozen before any optimisation.
Hidden goalsEach scenario carries a caller script and an expected end-state (which writes, with which arguments). The agent sees none of it.
Seeded stateEvery run starts from a reset ledger row keyed to that run, so two calls can never contaminate each other's evidence.
Blind splits60 scenarios are held out from the search entirely; a further fresh blind-30 was generated after the run finished, so it could not have leaked by construction.
Severity weightsSafety and fraud escalation ×3, guardrails and privacy ×2 — the search is paid most for the failures that matter most.

Validation metrics grade the test: a failure there voids the call as evidence rather than counting against the agent. Turn-taking is reported only where its per-turn audio segments exist; where the harness returns none, it is shown as “no data”, never as a zero folded into an average.

Making a silent failure loud: the transport gate

The single most dangerous instrument failure found in this project was not a wrong score — it was a plausible one. A dead tool tunnel produces exactly the same evidence as an agent that chose not to call tools: an empty journal. The system now refuses to confuse the two.

PreflightBefore any measured run: deployed prompt sha matches the pinned champion, agent clock is today's, tool service answers, gate accepts the key.
End-to-end probeA real turn is driven through the deployed agent and must land in the journal. Only this proves the whole path.
Refusal to scoreAn empty journal on an unverified transport is reported as "cannot conclude", never as a zero.

The instrument audit

Three faults were found in the measuring apparatus itself — not the agent — and each is reported because an evaluation that only audits the agent has not audited itself.

FaultHow it surfacedFix
Stale clockThe agent's injected currentDate went a day stale overnight. It resolved "kal" correctly against the real calendar; the grader compared against yesterday's. One family read 2/12 when it was 11/11.Clock synced from the real calendar at every run start and at dial time; the grader reads it live; a regression test greps the scoring path for date literals.
Expired token141 conversations returned HTTP 401 and were scored as behavioural failures. Caught by checking error fields rather than trusting totals. Contaminated rows purged and re-run; token freshness asserted before long runs.
Wrong transcript sourceIn bot-to-bot runs the judged "agent" text was the caller's speech recognition of the agent's audio. One call was penalised for a hallucinated sentence the agent never said; the baseline's own scores were understated. Agent turns rebuilt from the runtime's own transcription; every voice run re-scored from the corrected transcript. The correction raised the baseline too — the fix was to the instrument, not to the result.
