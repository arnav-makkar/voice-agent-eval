How it is measured

Before improving anything, build something you can trust

Every number on this site comes out of one machine: a fixed set of test situations, three ways of talking to the agent, and a permanent log that decides what actually happened.

The setup in one picture

What the 180 situations cover

Fifteen kinds of thing that go wrong on a collections call, twelve variations each. Frozen before any improvement work started, so the target could not move.

Money

Pay now, promise a date, claim already paid, ask what is owed, book a callback

Conflict

Refuse outright, dispute the amount, allege fraud, ask to be deleted from the database

Danger

Genuine distress, wrong person on the line, someone asking for a password or OTP

🎯

The dangerous cases are weighted heaviest. Getting a distress escalation or a fraud report wrong matters more than a routine payment, so those situations count triple when the system is deciding whether a change is an improvement.

The exact thresholds, for anyone who wants them

Two composites, both fixed before the campaign began. Accuracy combines task completion (must be a perfect 1.0), honesty (at or above 0.5) and detail fidelity (at or above 0.95, the strictest, because a mangled amount is a failed call). Experience combines progression, conciseness and turn taking.

The composite structure is adapted from an open source voice evaluation harness, credited on the Limits page. The task completion core was replaced with log grading.

The instrument checks itself

Three faults were found in the measuring equipment rather than the agent. They are listed here because an evaluation that only reports the agent's failures has not really been audited.

🕐 A calendar that drifted

The agent was told the wrong date overnight. It handled "tomorrow" correctly; the grader compared against yesterday. One category read 2 out of 12 when the truth was 11 out of 12.

🔑 An expired login

141 conversations came back as authentication errors and were being counted as the agent behaving badly. Caught by checking error fields instead of trusting the totals.

🎙️ The wrong microphone

In voice tests, the "agent" text being judged was the caller's speech recognition of the agent's audio. One call was penalised for a sentence the agent never said.

🔌 A dead connection

A broken tool connection produces the same evidence as an agent choosing not to act: an empty log. Every run now proves the connection end to end before it counts.

📈

Fixing the microphone fault raised the old agent's scores too. That is the point. A correction that only ever helps the new version is a correction worth distrusting.

How much wobble is normal

Run the same agent on the same tests twice and results move a little on their own. That was measured first, so no ordinary fluctuation could be mistaken for progress.
