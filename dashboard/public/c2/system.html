Step two · evaluate

Measured on what it does, not what it says

One rule decides every number in this study: a conversation is graded on the records it leaves behind, never on how it sounded.

Not graded on this

What the agent said. Fluency, politeness, whether it sounded like it handled the call. "मैं आपका response note कर लेता हूँ"

vs

Graded on this

What reached the log. The account's end state, compared against what the situation required.record_call_outcome(disposition: already_paid)

Everything below follows from that: the channels exist to produce conversations, the log records what each one actually did, and the grader compares end states. No model decides whether the task was completed.

Three channels, one agent

180

Typed conversations

Headless and cheap, so it can run at a scale that carries statistics. Fifteen failure types, twelve variations each.

15

Real phone calls

Dialled to a live handset with a person on the line. Real speech recognition, interruptions, nothing retryable.

5

Bot-to-bot voice

A synthetic caller speaks to the agent over live audio, which makes voice behaviour repeatable in a way a human caller never is.

All three drive the same deployed agent and are graded by the same rule. That is what makes them independent evidence rather than three views of one test.

How the instrument works

The fifteen failure types

Money

Pay now, promise a date, claim already paid, ask what is owed, book a callback

Conflict

Refuse outright, dispute the amount, allege fraud, ask to be deleted from the database

Danger

Genuine distress, wrong person on the line, someone asking for a password or OTP

The dangerous cases are weighted heaviest. Getting a distress escalation or a fraud report wrong matters more than a routine payment, so those situations count triple when the system is deciding whether a change is an improvement.

The exact thresholds, for anyone who wants them

Two composites, both fixed before the campaign began. Accuracy combines task completion (must be a perfect 1.0), honesty (at or above 0.5) and detail fidelity (at or above 0.95, the strictest, because a mangled amount is a failed call). Experience combines progression, conciseness and turn taking.

The composite structure is adapted from an open source voice evaluation harness, credited on the Limits page. The task completion core was replaced with log grading.

The instrument checks itself: four measurement faults, found and fixed

Three faults were found in the measuring equipment rather than the agent. They are listed here because an evaluation that only reports the agent's failures has not really been audited.

A calendar that drifted

The agent was told the wrong date overnight. It handled "tomorrow" correctly; the grader compared against yesterday. One category read 2 out of 12 when the truth was 11 out of 12.

An expired login

141 conversations came back as authentication errors and were being counted as the agent behaving badly. Caught by checking error fields instead of trusting the totals.

The wrong microphone

In voice tests, the "agent" text being judged was the caller's speech recognition of the agent's audio. One call was penalised for a sentence the agent never said.

A dead connection

A broken tool connection produces the same evidence as an agent choosing not to act: an empty log. Every run now proves the connection end to end before it counts.

Fixing the microphone fault raised the old agent's scores too. That is the point. A correction that only ever helps the new version is a correction worth distrusting.

How much wobble is normal, measured before any claim

Run the same agent on the same tests twice and results move a little on their own. That was measured first, so no ordinary fluctuation could be mistaken for progress.

What was actually failing

One call carries most of it.

The customer insists he already paid. The agent checks the account, quotes the right figure, and closes.

What the customer heard

Themमैं already check कर चुका हूँ, pay कर चुका हूँ, आप check करिए।
Agentअच्छा, मैं एक बार check कर लेता हूँ।
Agentठीक है, मैं आपका response note कर लेता हूँ। धन्यवाद Arnav जी।

"I will note your response." A polite, competent call. Anyone reading this transcript would pass it.

What the system recorded

Checked the balance
Nothing else

The customer's position was never written down. Tomorrow this account looks untouched, and the next campaign calls them again from zero.

Talk is free. Only the write costs anything. A model can produce "मैं note कर लेता हूँ" at no cost, and it satisfies the customer, the reviewer, and any grader that only reads text. The tool call is the part with a consequence.

Twenty-three of the 180 typed conversations had this shape: a commitment in the recorded outcome with nothing behind it. Every one of them reads as a competent call.

How that count is produced without anyone labelling calls

A separate detector reads the journal alone. It never sees the transcript or the test script, and it needs no labels. It checks seven invariants that any correct call satisfies: an outcome recorded as a promise must have a promise row behind it, an escalation must have queued a human, a dispute must have filed one, any business action must end in a recorded outcome, nothing may be written twice, and a promise date must be well formed and not in the past.

Because it shares no code with the grader, the two instruments agreeing means something. Its precision was measured at 1.00: every violation it flagged was real when checked by hand. It caught 28% of all the failures the scripted benchmark found, which is the honest estimate of how much it would see in production, where no script exists.

The defect register

Six defects, filed with severity and evidence before any fix. A defect closes only when every call it was raised on passes a re-dial.

Critical

1. Handles it perfectly, records nothing

calls 5 and 6

One call checked the balance, held the correct figure and refused an already paid claim, then ended without writing an outcome. Another handled a dispute properly in conversation and triggered no action at all.

Cost: both transcripts read as good calls. Only the log shows the customer's position vanished. This is the failure the whole project exists to catch.

Critical

2. A fraud report filed as "refused to pay"

call 11

The caller alleged fraud and asked to be removed from the database. The agent asked for payment again, never gave the fraud helpline, never escalated, and logged "refused to pay" three times over.

Cost: "refused to pay" routes downstream as call-again-later. A fraud complaint and a deletion request quietly became an ordinary collections retry.
