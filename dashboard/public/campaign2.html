Loopline · campaign 2 · EMI recovery voice agent

A voice agent that improved itself, and the evidence that it did

One deployed Sarvam Indus agent. A frozen benchmark graded from an append-only tool journal, never from what the agent said. Two autonomous optimisation cycles, no human-authored candidate text, gated on scenarios the search never saw.

The improvement architecture

GEPA is the search stage. A search algorithm on its own is not a self-improving system — it needs something to tell it what is broken, something to decide whether a change is real, and something to ship or revert it. Five stages, one growing memory.

SenseSeven say-versus-do invariants over the journal — a promise disposition with no promise row, an escalation code with no escalation call. No labels, no transcript. Measured precision 1.00.
DistillViolations cluster into ranked failure packets; recurring ones become new replay scenarios. The regression suite grows — this is the system's memory.
SearchGEPA proposes a candidate; Gemini 3.1 Pro reflects on per-scenario journal evidence. Applied to the live draft in ~1s over the authoring API.
GateBlind splits touched once, guardrail veto, McNemar on paired flips, and a noise floor measured before any candidate existed.
DeployDraft is staging, commit is production — the platform's own version model. Rollback is re-applying the parent, one call.

What makes it more than prompt-tweaking

  • The rollout target is the production system. Every candidate is evaluated by holding real conversations with the deployed agent, native tool execution included. No proxy model anywhere.
  • The reward is a side effect, not a sentence. Scores are read from the append-only journal. A spoken claim with no matching write scores zero — which is exactly how the dominant defect was found.
  • Two-component candidates. {instructions, exemplars}, evolved separately — MIPRO's insight grafted onto GEPA. An ablation puts 38% of the gain on the second component.
  • Explore, then consolidate. A first pass searches broadly; a second short pass is trained on the champion's own regressions. This replaces a human noticing what broke.
  • A stuck bucket. Scenarios two distinct prompts could not move are dropped from search attention — never from scoring — so the loop stops grinding on the unwinnable.

1,570 conversations in the optimisation run; ~2,700 across the campaign. Chat is credit-free, so search cost is bounded by evidence, not traffic.

The transfer test

Every number above this point is the text channel. The question a text result cannot answer is whether the same agent behaves that way on a phone line, where speech recognition is imperfect, the caller interrupts, and nothing is retryable. So the champion was re-run on both voice tiers against the same cards the baseline was diagnosed on.

The six diagnosed defects, re-tested

The baseline's phone failures were written up as six named defects before any optimisation ran. That makes them a pre-registered target: each one either closes on the champion or it does not, and a defect only closes when every card it was raised on passes.

The label-free monitor agrees with the benchmark independently: say-versus-do violations fell 23 → 2 at precision 1.00, from a detector that shares no code with the grader and never sees the scenario script.

What this does not claim

  • The voice tiers are small. The transfer test has now run — 15 phone cards and 5 bot-to-bot on the champion — and both moved in the same direction as the text tier. But n=15 and n=5 carry no statistics; they are existence proofs that the text-tier gains reach the voice channel, not measurements of how far.
  • One phone card's fix is confounded. Card 6 was run in English on the baseline (the caller switched language and the agent mirrored) and in Hinglish on the champion, so its fix is not isolated from that change.
  • Duplicate writes moved rather than resolved. Exactly-once ledger hygiene is 14/15 on both phone versions: the baseline's triple write on card 11 is gone, and a new double write appeared on card 13.
  • Compounding is not established. Gen 1 → Gen 2 is +5 overall at p = 0.18. Positive and regression-free; not proof that improvement compounds indefinitely.
  • Surface form matters a little. With every caller line reworded, the champion drops 29→26 while the baseline drops 18→17 — about 82% of the advantage survives.
  • Judges are designed, not built. The deterministic sensing layer runs; the LLM-judge layer is specified and calibrated against labelled data, but not yet in the reward path.
  • One account, scripted callers, uniform family mix. Correct for covering rare and dangerous cases; not a forecast of production traffic.
